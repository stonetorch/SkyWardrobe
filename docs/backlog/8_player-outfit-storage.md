# 玩家搭配存储方式

状态：待实现。确认日期：2026-10-16。

## 背景与目标

当前逐角色实现同时在 Wardrobe.json 和 SKSE co-save 中保存玩家搭配，读档时用 co-save 中的搭配覆盖 JSON，并再次写盘。这会使已独立保存的衣柜编辑在加载旧存档后回滚，也可能撤销安全模式中的服装修复。

提供“玩家搭配存储方式”设置，让用户明确选择“全局”或“存档局部”，避免两份数据互相覆盖。本需求仅调整玩家搭配的存储归属，不改变 NPC 的存储规则。

## 已确定的规则

### 全局配置

- “玩家搭配存储方式”是全局配置，保存在 `Data/SKSE/Plugins/SkyWardrobe.ini` 中，不随游戏存档恢复。
- 设置提供“全局”和“存档局部”两种模式。INI 键名、缺省值及设置界面位置在实施时确定。
- 存储模式切换本身不要求立即执行搭配迁移或文件清理；相关逻辑挂在对应的保存、读取行为上，平时不额外轮询处理。

### 全局模式

- 玩家搭配从持久化 JSON 读取，并保存到持久化 JSON；不依赖游戏存档保存。
- 保存、读取玩家搭配均忽略 co-save 中的玩家搭配数据，不将它们写入新的玩家搭配快照，也不从旧快照恢复。
- 不需要清空已有 co-save 中的玩家搭配数据。旧存档中的相关数据允许保留，但在全局模式下不参与加载和保存决策。
- 加载旧存档不得覆盖当前全局玩家搭配，也不得把旧搭配重新写回 JSON。

### 存档局部模式

- 玩家搭配由当前存档的 co-save 保存和恢复，游戏运行期间保留内存中的编辑状态。
- 搭配修改需要保存游戏存档后才持久化；重新加载旧存档恢复该存档的搭配。
- 不将玩家搭配写入持久化 JSON。
- 保存行为同步检查 JSON 是否遗留玩家搭配数据；若存在则清空，并持久化清理结果。清理挂在保存路径，不在空闲帧或模式切换时持续执行。
- 清理必须同时覆盖逐角色结构中的玩家搭配字段与根级玩家兼容镜像，避免旧读取或迁移逻辑再次恢复遗留数据。
- 清理仅针对玩家搭配，不删除其他角色、共享资源、服装组、预设定义及其他全局配置。

### co-save 的其他职责

- 模式仅决定玩家搭配的存储方式，不关闭整个 co-save 序列化。
- 临时物品记账、实际穿戴记录、动态角色引用绑定等存档相关数据继续按原有职责保存和恢复。
- 保存“玩家搭配”与保存“实际物品及引擎状态记账”必须区分，不能因为选择全局模式而停掉后者。

## 实施时需要明确的边界

- 列出玩家搭配字段的完整清单：工作搭配、后备搭配及其开关、原版透出与隐藏槽位、当前预设选择和基线等；明确自动模式、实际装备模式、自动结果及轮换进度的归属，避免同一组状态被两个来源混合恢复。
- 存档局部模式加载没有玩家搭配记录的旧存档时，需要明确初始化规则，不能无意继承上一个存档残留的内存状态。
- 模式切换后首次保存或读取如何选择当前搭配，需要明确，避免读取到过期 co-save 后悄悄覆盖用户刚刚编辑的内容。
- 存档局部模式的 JSON 清理失败应报告错误，不能声称遗留数据已清除；全局模式的 JSON 保存失败同样需要保留错误反馈。
- 安全模式仅暂停应用，不改变所选存储语义。局部模式中修复后的搭配需要保存游戏，重新加载未修复的旧存档会带回其旧搭配；界面需说明这一点。

## 验收要点

1. 存储方式写入 INI，重启后保持，加载不同游戏存档不改变该全局设置。
2. 全局模式编辑工作及后备搭配后，不保存游戏也能从 JSON 恢复；加载旧存档不会回滚编辑。
3. 全局模式忽略已有 co-save 玩家搭配，不清空旧快照，也不再写入玩家搭配；其他 co-save 记账仍正常保存恢复。
4. 存档局部模式的两个存档可拥有不同玩家搭配；保存游戏后分别读档，恢复各自的搭配。
5. 存档局部模式执行保存时，检查并清空 JSON 遗留的玩家搭配和兼容镜像；没有遗留数据时不做无关修改。
6. 空闲运行及单纯切换模式不触发额外清理轮询；NPC 和共享配置不受玩家搭配清理影响。
7. 覆盖旧存档缺少记录、模式切换后的首次保存/读取、写盘失败以及安全模式修复场景。
