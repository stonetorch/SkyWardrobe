# 服装组定义

服装组表示“一些服装的集合”，现有的分类、注册插件、预设等功能的抽象，用于统一这些功能的行为，取代预设功能

一个esp被注册时，就被添加为一个服装组，此时它并不会全量读取所有服装，还是走原来的直接读取路径，也就是记录一下esp来源

分类也被视为一种服装组，用户还是像以前一样往里面添加服装

服装组可以引用另一些服装组，在这种情况下，浏览服装组时可以点击被引用的条目快速跳转。引用显示方式就像服装一样，分列展示时默认在最左边。点击行为是跳转

服装组可以设置名称与别名，由esp注册的服装组也依旧提供默认直接显示模组名的功能

分类这一概念依然被区分，以便快速将服装添加到分类。只是说一个分类本质上视为一种特殊的服装组


## 如何取代 preset 功能

实际上并不是严格取代，preset现在表示“一个可以被一键应用的服装组，并可以加上一些自动化条件，应用预设本质上就是*使用服装组*”

*使用一个服装组*时，它会扫描组内所有服装（服装组引用并不考虑在内，不要自己加戏），然后**随机选择**一套不彼此覆盖的服装作为结果。

## 展示逻辑

虽然许多概念已经被统一为服装组，但是在操作时，它们依旧被分化为分类、注册的模组、其他服装组

## 快捷操作

整体逻辑：应用某些操作，进入快捷操作状态，此时点选服装不是再添加/移除活动工作区，而是使用这些快捷操作。此时在UI上显示正在进行某某快捷操作
高亮状态的语义也发生变化，具体取决于进行的快捷操作，高亮的颜色最好与原来的“已经加入活动工作区”作区分

1. 将服装添加到服装组（包括分类）。此时点击以添加，已经添加的再次点击会移除。高亮状态表示服装是否已经在组内
2. 将服装标记为某一个 part。点击以修改 part 归属
3. 将服装移除当前服装组。点击以移除（但是对于已注册模组这类特殊服装组而言，无法移除）
4. 从当前服装组创建子服装组：其实是一个组合操作，先创建一个新的服装组，命名为"当前服装组名字-递增数字id"（数字id要自己扫描一个不重复的），创建双向引用，然后进入“将服装添加到服装组”快捷操作模式

## 其他交互

其实服装组就展示在现在的衣柜，不需要改名、不需要新建tab。对于分类、注册模组、其他服装组
- 都需要展示对应的编辑元数据按钮（弹出弹窗提供分类管理、注册模组管理里面的那些选项）
- 都需要提供“使用服装组”的按钮
