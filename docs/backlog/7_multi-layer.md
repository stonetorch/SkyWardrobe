# 多层服装覆盖、后备搭配与原版装备显示

本文记录多层外观设计。2026-10-14 已按用户“开工”授权实现，下文推荐细节采用第7节记录的实施选择；验证结果见 [实现报告](../reports/7_multi-layer-report.md)。

## 1. 目标与术语

- 允许角色实际穿着的装备透出，并按装备位置隐藏其中一部分。
- 工作搭配拆成上下两层：上层继续称为“工作搭配”，下层称为“后备搭配”。应用服装组修改上层，下层允许独立配置，并逐角色保存。
- 上层缺少装备时显示下层；下层也没有时，允许经过隐藏过滤的原版装备显示。
- “原版服装／原版装备”指角色通过游戏装备系统实际穿着的装备，包括模组装备，不限定为 Skyrim.esm 的物品。
- “服装组”表示资源集合；“搭配”表示已经选定、参与外观合成的装备列表。后备搭配可以从服装组选取，也可以逐件编辑。

## 2. 已确定的分层结构

合成顺序从低到高：

```text
1. 角色实际穿着的原版服装
             ↓
2. 隐藏 filter：过滤原版层
             ↓
3. 后备搭配覆盖
             ↓
4. 工作搭配覆盖
             ↓
         最终外观
```

隐藏 filter 是底层过滤操作，参与覆盖的服装层共有三层。最终优先级为：工作搭配 > 后备搭配 > 过滤后的原版装备。

- 应用服装组只替换工作搭配，保留后备搭配和原版隐藏配置。
- 工作搭配移除装备后，允许后备层透出；后备层也没有对应装备时，允许原版层透出。
- filter 只隐藏原版来源的装备。同一位置上的后备装备和工作装备仍可显示。
- 工作搭配、后备搭配和原版隐藏配置逐角色隔离；服装组、服装资源、别名及分类继续全局共享。
- 切换编辑角色沿用角色管理方案：展示该角色配置，切换本身不应用外观。

示例：角色实际穿着铁甲、铁靴、护手，filter 隐藏铁甲，后备搭配包含假发和高跟鞋，工作搭配只有裙子。最终显示裙子、后备假发、后备高跟鞋和原版护手。工作层加入自己的鞋子时覆盖后备鞋子；移除后，后备鞋子重新显示。

## 3. 已确定的编辑操作

保留中间服装卡片现有左键语义，后备编辑使用右键菜单和右侧条目按钮。无需增加“添加到”目标选择器或“编辑中”模式，展开哪个区块也不改变左键目标。

| 位置 | 操作 | 行为 |
| --- | --- | --- |
| 中间服装卡片 | 左键单击 | 沿用现有工作搭配加入／移除行为 |
| 中间服装卡片 | 左键双击 | 沿用现有工作搭配应用行为 |
| 中间服装卡片 | 右键“添加到后备搭配” | 添加到当前角色后备搭配 |
| 右侧工作搭配条目 | 发送到后备的小按钮 | 将条目发送到后备搭配 |
| 右侧后备搭配条目 | 发送到工作的小按钮 | 将条目发送到工作搭配 |
| 右侧搭配条目 | × | 从所在层移除 |

推荐将“发送”定义为移动：目标层加入成功后从来源层移除。右键“添加到后备搭配”仅添加，保留工作层已有的同件装备。本次实现采用此区别，见第7节实施选择。

推荐条目布局：

```text
工作搭配
[×] [↓] 连衣裙
[×] [↓] 高跟鞋

后备搭配
[×] [↑] 常用假发
[×] [↑] 默认鞋子
```

- 箭头与层级方向对应，悬停分别显示“移到后备搭配”“移到工作搭配”。
- 小按钮保持固定宽度、单行排列；长名称截断，悬停显示完整名称。
- 目标层内部沿用槽位冲突替换规则；两层之间允许保留冲突装备，否则无法实现后备。
- 目标层已有同件装备时去重；若采用移动语义，仍移除来源层条目。
- 一次发送作为完整操作保存一次，实时预览只提交最终结果一次。
- 推荐发送后保持来源区块展开状态，更新目标件数，便于连续操作。
- 推荐后备关闭时仍允许编辑，但编辑不自动启用，标题明确显示关闭状态。
- 常规“应用服装组”固定更新工作层；另提供明确的“设为后备搭配”操作。

## 4. 推荐的合成与过滤规则

### 4.1 槽位冲突与整件装备

“上层没有”按实际选中的装备及真实 biped 槽位判断，部件分类用于组织和解释。上层没有标记为“头发”的成员，但头盔占用了后备假发的槽位时，仍应排除后备假发。

推荐采用整件装备规则：

- 高层与低层装备有任意真实槽位冲突时，排除整件低层装备。
- 原版装备任意占用槽位命中隐藏 filter 时，隐藏整件装备。
- 多槽位连体服不承诺局部拆分显示；界面说明受影响的整件装备及全部关联位置。
- 各层内部生成不冲突的搭配，跨层覆盖采用明确优先级，不依赖 SOS 的集合迭代或槽位遍历顺序。

### 4.2 原版隐藏设置

推荐将 filter 保存为槽位规则，而非当前装备名称；更换实际装备后，相同位置继续遵守配置。

日常视图同时说明当前实际穿着什么，以及最终哪些原版装备正在透出。已隐藏、被覆盖的装备仍可查看并恢复显示。

| 位置 | 当前实际装备 | 原版显示设置 | 最终状态 |
| --- | --- | --- | --- |
| 头部 | 铁头盔 | 隐藏 | 被隐藏 |
| 身体 | 铁甲 | 允许 | 被工作搭配覆盖 |
| 手部 | 铁护手 | 允许 | 正在透出 |
| 脚部 | 铁靴 | 允许 | 被后备搭配覆盖 |

推荐默认只展示实际有装备的条目，同一件多槽位装备只列一次并附关联位置。通过“配置全部位置”弹窗配置完整槽位，包括当前空位置。

### 4.3 后备内容稳定性

推荐从服装组设置后备搭配时生成一次，并保存选定装备列表。应用工作服装组、实时预览和原版装备刷新时保留后备结果，需要换一套时再主动重新选取。避免每次刷新都随机更换后备发型或鞋子。

装备式假发属于该模型；角色原生发型不属于 ARMO 服装列表，其显示异常需独立追踪。补位解决鞋子外观是否存在，高跟高度继续使用现有实际装备方案并单独验证。

“主动留空、阻止所有低层透出”作为后续可选能力，本阶段移除装备的含义保持为允许低层透出。

## 5. 推荐的右侧布局与高度自适应

三个入口继续放在整个衣柜面板右侧，从上到下为工作搭配、后备搭配、原版服装显示。使用可折叠区块，标题显示件数、启用状态或原版透出／隐藏数量。折叠标题与左侧导航一致，使用 ImGui 原生大三角箭头，不使用字符 `v` / `>` 模拟箭头。

```text
当前操作角色
[玩家                    ▾]
未命名搭配
☑ 实时预览   [应用] [更多 ▾]
实际装备：仅鞋子 ▾
────────────────────────────
▼ 工作搭配                 7件
  [×] [↓] 装备条目
────────────────────────────
▼ 后备搭配       ☑启用     2件
  [×] [↑] 装备条目
────────────────────────────
▼ 原版服装显示     透出3 / 隐藏2
  装备、位置、显示开关及结果状态
```

### 5.1 公共操作

- 右侧栏最上方放置当前操作角色选择器，随后保留搭配名称、实时预览、应用和实际装备模式。
- 推荐将覆盖当前预设、恢复预设、撤销上次覆盖及清除外观覆盖放入“更多”。清除是否保留直接按钮仍待确认。
- 公共操作与各层内容分开，避免重复按钮占用三层列表空间。

### 5.2 正常高度

- 先保留公共操作和三个层标题的高度。
- 展开区按实际条目数申请高度，短列表只使用需要的空间，折叠区只保留标题。
- 内容能全部放下时完整显示；放不下时压缩长列表，工作搭配获得最多空间，其他展开层保留少量可见行。
- 空间分配比例仅作为不足时的倾向，不采用固定三等分；短列表和折叠释放的空间分给其他层。
- 使用当前字体行高、间距和 UI 缩放计算尺寸，具体最小可见行数在实现时验证。

### 5.3 小高度与紧凑布局

- 容器不足以让三个展开区各显示合理行数时，进入紧凑布局，一次仅展开一层，当前层使用剩余空间。
- 三个标题继续上下排列并保持可见，点击另一个标题切换展开层；无需改成另一套 Tab 布局。
- 进入紧凑布局时优先保留用户最近操作／展开的层，无记录时默认工作搭配。此记录仅用于布局，不改变中间卡片左键目标。
- 恢复足够高度时恢复此前正常布局的展开状态。
- 切换依据容器可用高度及缩放，添加／删除条目不触发模式跳变；切换阈值留出余量，避免窗口缩放时反复切换。

### 5.4 滚动与极小尺寸

- 公共操作和层标题常驻；展开列表内部滚动，避免右侧整体滚动与内部滚动叠加。
- 正常布局可有多个独立列表，滚轮作用于鼠标所在列表；紧凑布局仅有一个展开列表。
- 最小面板高度应能容纳公共操作、三个标题和可操作的列表空间，并随字体缩放计算。
- 一键发送不强制展开目标层或跳转滚动位置。

## 6. SOS backend 与实际装备边界

讨论时核对了 SOS 上游公开接口和显示集合实现：

- [原生接口声明](https://github.com/lispcoc/SkyrimOutfitSystemSE/blob/master/src/papyrus/skyrimoutfitsystemnativefuncs.psc) 提供实际穿着装备读取和逐槽位／整体策略设置。
- [显示集合与策略实现](https://github.com/lispcoc/SkyrimOutfitSystemSE/blob/master/src/rust/sos/src/outfit.rs) 按槽位选择整件装备，选中后占用该件全部槽位。
- `XEOO` 可表达 Outfit 优先、实际装备补空；`XXOO` 只显示 Outfit；`XXXX` 不选择任何装备。策略代码留在 backend 内，不进入日常用户操作界面。

推荐 SkyWardrobe 负责读取实际装备、底层过滤、三层冲突解决及来源说明，生成最终外观集合后交给 SOS。对运行时 Outfit 显式设置策略，避免被过滤的原版装备再次自行透出。实际安装版本的接口兼容和游戏效果仍需实现阶段验证。

最终外观列表与实际装备候选分别计算：原版透出项不因出现在外观列表就重新装备；工作／后备项是否真实穿戴遵循实际装备模式。保留临时装备来源记账，避免衣柜创建的临时物品误进入原版底层，在上层移除后再次透出。真实穿戴会改变角色实际装备，不能以旧底层快照永久代表当前状态。

原版装备变化后需要更新底层快照与最终结果；本插件真实穿戴引发的装备事件应合并处理，避免重复刷新循环。更新原版层不重新抽取工作或后备搭配。

逐角色 backend 请求捕获具体角色并使用独立运行时 Outfit，沿用 [角色管理与自动换装方案](6_life-improvement.md) 的隔离和生命周期约定。

## 7. 实施选择（2026-10-14）

用户授权开始实现后，对讨论中的推荐细节采用以下选择：

1. 发送执行移动，右键添加仅添加。目标去重、目标层冲突替换，保留跨层冲突。
2. 多槽位装备整件覆盖／隐藏，filter 按槽位持久化。
3. 后备保存一次选取结果并可关闭；迁移为空后备，原版穿透默认关闭。
4. 正常高度按内容分配；剩余区高度少于12行进入紧凑布局，多于13行恢复；最小窗口高度按19行计算并受 viewport 限制。
5. 预设相关操作、清除和最终来源预览放入“更多”。
6. 原版区逐件展示当前实际装备，全部32个位置在弹窗配置。
7. 预设只保存工作层；后备、filter 是角色长期设置，读档时以对应 co-save 配置恢复。覆盖预设不会写入后备或原版合成项。
8. 原版穿透提供总开关；清除退出全部覆盖，保留各层配置。主动留空继续作为后续能力。

## 8. 后续实现验收

- 应用工作服装组保留角色后备层和 filter；角色之间配置与运行时请求隔离。
- 工作、后备、原版三层覆盖结果符合优先级；多槽位冲突和隐藏结果可解释。
- 左键始终操作工作搭配；右键可添加到后备；右侧两个方向按钮按最终确认的发送语义执行。
- 删除上层项后正确透出低层；跨层冲突装备保留在各自配置中；一次发送只保存并预览最终结果一次。
- 原版已隐藏、被覆盖和透出项可查看；实际装备变化更新结果，刷新不重新随机选择搭配。
- 不同面板高度、字体缩放、空层、短列表、长列表及长名称下，三个入口可访问，按钮可操作，列表滚动正确，紧凑切换稳定。
- 最终结果能说明来源和隐藏／覆盖原因；实际装备模式与临时装备记账不造成低层重复透出或刷新循环。
- 迁移保留已有工作搭配与用户数据。纯合成逻辑使用有意义的模型测试，C++ 验证按仓库 AGENTS.md 的构建入口执行；游戏内验证单独记录 SOS 多槽位外观、原生头发和高跟行为。

## 9. 界面修正（2026-10-14）

- 旧版右侧三个折叠标题使用字符 `v` / `>`，现改为与左栏相同的原生折叠箭头；保留按高度分配空间与紧凑布局的展开状态管理。
- 当前操作角色从主面板横跨整行的位置移到右侧栏最上方。
- “设为后备搭配”与前后服装组操作按钮同行显示。快捷操作批量按钮的旧版错误理解及修正规则见 [第6项 backlog](6_life-improvement.md#界面与语义修正2026-10-14)。
- 本次修正已通过 C++ 编译与 DLL 链接，`git diff --check` 通过；提权构建脚本在后续自动复制 DLL 时因 `Permission denied` 返回1。未执行游戏内界面验收。
