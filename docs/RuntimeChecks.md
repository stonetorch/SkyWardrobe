## 可选实际装备验收

记录 Skyrim runtime、SKSE、SOS、RaceMenu/高跟高度修复模组版本。本功能已实现原版穿戴路径，高跟高度是否恢复仍需这组游戏验收确认。

2. “仅鞋子装备”：工作搭配含上衣、槽位 37 的高跟鞋、仅槽位 38 的袜子。应用后只实际穿上鞋，上衣和袜子走 SOS；比较同一双鞋在物品栏装备与衣柜应用后的高度。多槽位鞋仍应实际装备。
3. “全部装备”：实际穿上整套工作搭配，检查护甲与附魔效果。玩家已有强化/附魔服装不增加数量，实例数据保留；缺少服装只添加一件，重复应用不累计副本。

## 外部输入法验收

三个 provider 分别单独安装运行，记录 Skyrim runtime、SKSE、输入法 DLL 版本和 Windows 输入法。检查设置页和 `SkyWardrobe.log` 的 `External IME provider` 与实际安装一致。没有外部模组时英文 / Ctrl+V 应保持可用；同时安装多个已知输入法 DLL 时显示冲突，衣柜不主动申请输入法焦点。

1. SimpleIME：候选窗位置设为 Follow Cursor 或 None。搜索、别名、备注分别组词，测试空格、数字、方向键选词，Enter 确认和 Esc 取消。首次 Esc 取消组词时衣柜不能关闭，之后退出文本编辑，再按 Esc 关闭衣柜。
2. Skyrim Input Method：执行相同检查，尤其确认顶层菜单收到上屏文字而非控制台、字母拼音不同时进入输入框、组词方向键不移动编辑光标。
3. Input Method Unlocked：窗口 / 无边框模式下使用 IMM 兼容输入法测试。确认过滤后的游戏字符与退格直接进入衣柜，不打开 `SkyWardrobe Text Input` 菜单。分别用空格与数字选词；组词时退格仅删拼音，组词清空后再退格删输入框文字。切换中文 / 英文后英文正常上屏；点击非文本区域结束编辑应出现 `IME text lease released`，再次点击输入框只申请一次。Esc 在组词时取消组词，之后退出文本编辑，再次按下关闭衣柜；长按退出编辑的 Esc 不应顺带关闭。一次提交超过五字的整句，记录实际版本是否完整；发布版 2.0 与本次读取的 2.1.0 main 行为需分别记录。候选窗不可见暂不作为本次修复的验收项。
4. 每种 provider 都输入“裙裙”和中英文标点，检查无去重、无重复、无乱码。Ctrl+V 中文长句只粘贴一次；菜单型输入法自身 Unicode 粘贴分别启用 / 禁用，回退仍应工作。
5. 组词时切换输入框、点窗口关闭、Alt+Tab、切控制台 / 原生菜单、新建或读档，再次打开检查旧字符不会进入新字段，Ctrl / Shift / Alt 不会卡住，候选窗退出且原生文本输入恢复。
6. 调整 UI 缩放后检查候选窗可用；拖动窗口、卡片点击和鼠标命中位置不变，键盘输入不触发玩家移动或攻击。打开 SimpleIME 工具窗口时检查菜单接管和恢复。

2026-10-05，用户在 Skyrim 1.5.97 / IMU 2.1.0 环境报告初版输入异常，修正后确认问题已修复。该反馈针对 IMU 报告的问题；以上完整矩阵、另外两个 provider、候选窗及跨输入法表现没有逐项验收记录。离线逻辑测试与编译成功只验证编码、路由策略和源代码构建。过程及完整输入流程见 [ImGui 中文输入完整报告](reports/imgui-chinese-input-retrospective.md)。
## 安全模式验收（待游戏内执行）

记录测试所用 Skyrim/SKSE 版本；以下项目需要在实际游戏中验证，编译和文件测试不代替运行时结果。

- 正常退出到桌面后重新启动，不应自动进入安全模式；分别检查游戏菜单退出与控制台正常退出。返回主菜单和读档不应清除 `Session.running`。
- 强制结束游戏后重新启动，应在首次 WA 换装前进入安全模式；在安全模式内再次异常结束，下次仍应进入。
- 分别使用 INI 和多个不同大小写、后缀的 SAFEMODE 文件启动；WA 应显示进入原因，衣柜、预设、组编辑保存可用，预览和应用暂停。
- 自动、手动、快捷入口、角色重新加载、多层刷新及实际装备模式在安全模式中不应发出服装操作；加载不同存档或重载 JSON 仍保持安全模式。
- 运行中进入应取消旧队列及后续异步步骤；移除问题工作服装和组成员后退出，应保存完成、删除全部匹配文件，并按修复后的数据恢复，不重放旧自动快照。
- 锁定触发文件或制造保存失败，退出应失败并保留安全模式；MO2 下验证删除后的文件不会从较低优先级模组重新出现。普通文件、目录及子目录内容均应保留。
- 保留 `safe_mode=1` 时面板可退出当前会话，下次启动再次进入；关闭自动异常退出检测后，文件及 INI 手动入口仍有效。
- 正常模式主面板顶部不显示“进入安全模式”；在“界面设置”中可进入。切换“异常退出后自动进入安全模式”并重启，检查开关持久化以及异常退出后的对应行为；调整缩放、快捷键等界面设置后，INI 的手动安全模式开关及其他配置仍保留。

## 内置操作手册验收（待游戏内执行）

- 从“界面设置”打开手册，确认出现独立小窗口；目录可进入全部 13 个主题，上一页、目录、下一页及相邻主题名称正确，首尾导航不会越界。
- 保持手册打开并切换标签页，确认金色箭头先指向目标标签，再随可见控件更新；拖动和调整主窗口、滚动衣柜区域后没有残留坐标，目标被手册遮住时拖开可恢复指引。
- 检查工作搭配、新建服装组、后备、原版透出、实际装备、搜索和快捷操作教程的箭头位置；展开／折叠搭配层后指引仍落在当前可见入口。
- 点击手册内全部示例控件，确认工作／后备搭配、服装组、当前角色和预览状态均不变；点击真实控件仍执行正常业务操作，弹出菜单时指引线暂时隐藏。
- 在不同界面缩放和分辨率下检查正文可滚动、底部导航可见，翻页回到正文顶部；关闭后重新打开回到目录。记录实际 Skyrim / SKSE 版本及中文或英文构建。


## 玩家搭配存储方式

记录本次验收的 Skyrim / SKSE 版本，以下场景需要实际游戏验证：

1. 设置切为全局，修改工作与后备搭配、分层开关、自动模式及实际装备模式，不保存游戏后重启；确认从 JSON 恢复。加载带旧玩家快照的旧存档，当前搭配与轮换进度不回滚。
2. 全局模式保存后，确认 co-save 记录 5 没有玩家条目；临时物品清理、实际穿戴记录、SOS 原自动切换值和动态 NPC 引用仍能随存档恢复。
3. 局部模式分别保存 A / B 两套不同搭配及自动进度；反复读取 A / B，确认逐档恢复。读取没有记录 5 或没有 player 条目的旧档，以及开始新游戏，确认玩家从空搭配开始。
4. 检查局部保存后 JSON 同时移除 actors.player 中的搭配字段与根级兼容镜像；NPC、共享元数据、服装组、预设定义及固定默认绑定保持。没有遗留数据时再次游戏保存不得仅为清理重写 JSON。
5. 单纯切换模式保留当前内存搭配；切到全局后首次衣柜保存写入当前搭配，切到局部后首次游戏保存写入当前搭配；切换后的首次读档遵守新模式。空闲帧不产生清理轮询。
6. 拒绝 INI / JSON 写入权限，分别验证模式设置回滚、全局保存和局部清理错误提示，恢复权限后重试。
7. 安全模式中加载两份局部存档应分别恢复其搭配；修复后保存游戏再读回验证。读取未修复旧档仍恢复旧搭配。全局模式中的修复不被旧 co-save 回滚。
