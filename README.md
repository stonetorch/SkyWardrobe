# SkyWardrobe

Skyrim SE / AE 的独立 SKSE 衣柜管理器。扫描已加载的 ARMO 资源，以 UTF-8 JSON 管理别名、备注、收藏、分类、语义部件与预设；Skyrim Outfit System SE Revived 负责最终外观覆盖。默认只改变外观，可选通过原版路径同时实际穿戴鞋子或全部服装。

## 使用

运行依赖：匹配游戏版本的 SKSE、Address Library，以及 [Skyrim Outfit System SE Revived](https://github.com/lispcoc/SkyrimOutfitSystemSE)。SOS 未安装或原生 DLL 未加载时，SkyWardrobe 全部功能禁用，面板只显示依赖缺失提示，不会尝试 VM 调用。安装兼容版本后需要重启游戏。SOS 需在自己的 MCM 中启用。

控制台命令无需 ESP、Papyrus 编译产物或 ConsoleUtil：

```text
wardrobe
wa
sa
wardrobe reload
wardrobe preset "city-black"
wardrobe clear
wardrobe close
```

`preset` 支持预设 ID 或完整名称。`wardrobe` 打开后自动关闭控制台。关闭按钮和 Esc 恢复游戏视角输入；外部输入法编辑期间，Esc 先由输入法取消组词或退出文本编辑，再按 Esc 关闭衣柜。界面设置可以启用 / 禁用快捷键并重新绑定；默认禁用，预选 F11。窗口可拖动与调整大小，布局保存在 `SkyWardrobe/ImGui.ini`；UI 缩放与鼠标灵敏度分别设置。

## 衣柜功能

- **全部服装、★ Favorites、未分类、工作搭配**：左侧切换视图。原始目录只扫描，不批量写入 JSON。
- **注册插件**：在“分类与数据 → 注册插件分类”勾选 ESP / ESM / ESL，分类动态包含其全部来源 ARMO，显示记录数量。覆盖原有 ARMO 的补丁不会把服装移出来源插件分类。
- **多对多分类**：创建分类，右键服装勾选多个分类；分类可重命名、增加拼音搜索词或删除。
- **服装卡片**：标题使用别名或原名，备注使用灰色小字号；悬浮显示完整文字、稳定 ID 与 biped mask。右键编辑收藏、别名、中文备注、搜索词、分类与部件。
- **搜索**：名称、别名、备注、插件、分类和搜索词共同参与匹配。中文通过 cpp-pinyin 自动生成全拼及首字母索引，`裙子` 可用 `qun zi`、`qunzi`、`qz`、`qzi`、`qu zi` 搜索，分类及预设同样支持；已有 `pinyin` / `search` 用于人工纠音和扩展搜索词。中文通过 Ctrl+V 粘贴，批量数据可直接编辑 JSON。
- **语义部件**：全身、上装、下装、内衣、胸衣、内裤、鞋、袜、手套、头饰、头发、项链、披风、配饰与自定义 1–8。自定义部件可以改显示名称。未标记服装按常见 biped 槽位给出初始建议，用户标记始终优先。
- **部件分列**：只显示当前结果中有服装的部件；在“Interface / 界面设置”中设置按部件分列、自动调整列布局及列数（1–12）。自动调整先分配空余列，仅在设置列数全部占用后才按可用高度合并较短的部件分类，计入分类标题、卡片、间距、分类上方留白及内边距，合并列完整展示所有项目且无需滚动；腾出的列优先分给仍需滚动的部件。窗口高度、字体缩放或筛选结果变化后重新计算。容纳不下的独立列保留各自的纵向滚动，总列数超出设置时水平滚动。
- **工作搭配**：单击卡片加入；重复点击保持选中。占用相同 biped 槽位的旧部件会被替换。右侧可移除部件；双击或“应用外观”应用整体搭配。实时预览默认开启，可关闭并保存选择。

- **多层外观**：每角色独立保存工作搭配、后备搭配及原版隐藏位置，优先级为工作 > 后备 > 过滤后的实际装备。应用服装组只更换工作层；“设为后备搭配”生成并保存一次后备结果。左键仍操作工作搭配，右键可添加到后备，右侧上下箭头将条目移动到另一层。后备层可独立关闭，跨层允许保留冲突装备。
- **原版透出**：默认关闭以保持旧搭配行为，在右侧原版区开启。按位置过滤，命中任一隐藏位置会隐藏整件多槽位装备；可查看实际穿着、透出、隐藏、覆盖及临时实例状态，“配置全部位置”支持空位置。每0.5秒合并实际装备变化，不重新抽取搭配；衣柜创建的临时穿戴实例不参与底层透出。
- **右侧分层面板**：三个区块按内容分配高度，小高度时只展开一层；各列表独立滚动。预设覆盖、恢复、撤销、清除和最终来源预览位于“更多”。预设覆盖仅保存工作层；后备和隐藏配置为角色长期设置。清除退出全部覆盖并保留配置。

- **实际装备**：工作搭配面板提供“关闭”（默认）、“仅鞋子装备”、“全部装备”。启用后，SOS 外观回读成功才通过原版 `ActorEquipManager::EquipObject` 穿戴对应服装；鞋子按脚部槽位 37 判断，语义部件标签不影响实际装备。模式按角色保存，启用模式在下次应用时生效；切到关闭立即安排临时物品回收，SOS 外观继续保留。实际装备会改变护甲、附魔及装备效果。

- **物品与回收**：玩家已有服装使用原物品实例，缺少的服装自动添加一件。启用模式下切换搭配，卸下衣柜此前实际穿上的、不再需要的服装，回收不再需要的临时物品；清除外观或关闭实际装备时，只卸下并回收临时物品，玩家原有物品保持当前穿戴，不恢复被替换前的装备。临时物品按原版唯一标识定位，记账随 SKSE co-save 保存；已移出玩家物品栏的物品不会在其他容器里被删除，也不会按同款 FormID 替代回收。
- **预设与服装组**：默认每个角色固定一套换装规则，预设搜索、切换和新建 / 删除入口隐藏。“界面设置”可开启默认关闭的“多预设（增强功能）”。旧角色的当前预设首次迁移为默认，额外预设保留。工作搭配页的“从工作搭配新建服装组”只保存衣服成员，不创建或切换预设。工作搭配与规则分离；“更多”中仍可覆盖默认服装组、恢复及撤销上次覆盖。
- **清除外观覆盖**：设置当前角色 SOS Outfit 为空并刷新该角色，工作搭配和已保存预设保留。未启用 SkyWardrobe 自动换装时，SOS 自身的地点 / 战斗自动换装仍可能再次选择服装；启用后由 SkyWardrobe 管理该角色的自动切换。

外观应用支持玩家与已管理人物。角色管理 Tab 可添加打开面板前注视的人物、选择附近人物或移除管理；主衣柜角色选择器始终把玩家放在第一位，切换角色不应用外观。角色按引用识别，工作搭配、预设、实际装备及临时物品记账相互隔离。每角色独立运行时 SOS Outfit：`__SW_<稳定角色键的 64 位摘要>`，不将每个 JSON 预设复制为 SOS Outfit。快速请求按角色合并并串行执行；新请求取消同角色旧回调链，不丢其他角色请求；加载游戏时取消旧世界回调链。后台检查 API 启用状态、完整解析所有 FormKey，依次覆盖 / 设置 / 刷新并回读当前 Outfit。缺失服装时拒绝应用整个预设，并显示缺失 ID。

## 导航与自动换装

侧栏顶部搜索与固定入口不滚动，下方分类服装组、普通服装组、注册模组共用滚动区域。普通服装组使用单层“目录”整理，可折叠、拖动排序、跨目录移动；右键“移动到…”支持开头、末尾、第 N 位和指定条目前后。注册模组固定在底部并保留插件文件名顺序，也可移入普通目录排序，此时仍按插件来源取服装，不能手工增删成员；同一条目不重复显示。

衣柜工具栏的“选取全部结果”“取消选取全部结果”作用于当前视图的全部搜索结果，包括需滚动才能看到的服装。普通模式修改当前角色工作搭配，快捷模式修改组成员或部件标记；批量操作只保存一次、预览一次。工作搭配仍会替换冲突槽位，组成员全部保留。取消部件标记只清除匹配的用户覆盖，回退别名包或自动识别。

预设按角色配置，默认固定使用一套默认预设；开启多预设增强功能后才可管理并切换其他预设，同一角色同时启用一个。条件优先级为战斗、地下城、城市、城镇、默认；地点按关键词及父地点判定。每个条件支持单组、随机组（多个候选避免连续相同）与固定顺序循环，组内仍沿用随机槽位互斥搭配，引用不递归收集。随机与顺序规则支持“用服装组作为列表”：动态读取指定普通服装组全部直接引用，按引用顺序作为候选，不递归展开，不混入该组自己的衣服成员。也可手动搜索添加、拖动及右键精确移动候选。每个条件可勾选“继续采用工作搭配”，命中后直接使用当前角色的工作搭配，优先于该条件候选组且阻止匹配低优先级条件；空工作搭配也不回落。自动判断每 0.5 秒在游戏线程采样，暂停菜单期间不换装；状态采样、条件采纳、外观应用分三层执行。状态变化连续两次采样确认（约半秒），各条件独立去抖；条件采纳仅看稳定状态与启用设置，不读取服装组。仅采纳条件变化、初次启用或显式重新应用时才解析候选成员并生成搭配，应用成功才推进轮换。未启用的条件或被高优先级规则遮住的地点变化不会重新随机或推进顺序；持续轮询和装备层刷新复用已有搭配。战斗结束恢复战斗前搭配并保留战斗轮换进度；已应用结果及进度通过 co-save 恢复，动态人物引用通过 SKSE 重映射。

手动编辑暂缓该角色自动换装，下一次条件切换恢复，或点击“恢复自动”。关闭衣柜保留手动外观。启用自动换装时记录并关闭该角色 SOS 地点自动切换；关闭自动或移除管理时恢复原值。未加载角色的清理和恢复会延迟执行。旧预设迁移到玩家的默认条件，自动初始关闭。详细实现与验证见 [操作改进报告](docs/reports/6_life-improvement-report.md)。

## IME 集成

界面设置提供 **IMM shared [1]**、**IMM private [2]**、**外部模组桥接 [3]**、自动选择与禁用模式，并带有两组快速测试输入框。原生 IMM 不依赖输入法修复模组，按 Unicode 接入各语言；共享模式复用窗口上下文，独立模式在编辑期间创建自有上下文。每条路径可持久禁用。设置、兼容性边界和独立模块迁移方法见 [通用 IME 集成](docs/PortableIme.md)。

自动接入 **SimpleIME**、**Skyrim Input Method - Use System's IME**、**Input Method Unlocked**，无需为衣柜安装额外桥接 DLL。三种接入均已编译实现；IMU 在 Skyrim 1.5.97 / IMU 2.1.0 环境修正后得到用户成功反馈，另外两种仍需分别游戏验收。只启用其中一个输入法模组；同时加载多个时衣柜不申请外部输入法焦点，设置页显示冲突提示。

SimpleIME 的候选窗位置请设为 **Follow Cursor** 或 **None**，其 GFx 光标定位无法直接跟随独立 ImGui 插入点。Input Method Unlocked 的运行限制依其安装版本而定，窗口 / 无边框模式及 IMM 兼容输入法是作者公布的支持范围。已加载已知外部输入法模组时，原生 IMM 不接管窗口；纯 TSF text store 尚未实现。原生模式的各输入法及全屏候选窗行为仍需游戏内验收，Ctrl+V 保持可用。

界面设置显示识别到的输入法。搜索、别名、备注等标准文本框共用接入；焦点退出、关闭衣柜、切出游戏或读档会清理本模组申请和待处理文字。实现与来源见 [输入法接入说明](docs/InputMethodIntegration.md)，游戏验收见 [RuntimeChecks](docs/RuntimeChecks.md)。

信息搜集、初版失败分析、最终关键代码及完整输入流程见 [ImGui 中文输入兼容完整报告](docs/reports/imgui-chinese-input-retrospective.md)。

## JSON 与字体配置

```text
Data/SKSE/Plugins/
├─ SkyWardrobe.dll
├─ SkyWardrobe.ini
└─ SkyWardrobe/
   ├─ Wardrobe.json
   ├─ Wardrobe.json.bak
   ├─ ImGui.ini
   ├─ AliasPacks/*.json
   ├─ Fonts/fa-solid-900.ttf
   └─ Examples/
```

首次保存时创建数据库。配置示例在 [assets/examples](assets/examples)，格式说明见 [docs/DataFormat.md](docs/DataFormat.md)。示例不会覆盖正式配置文件，也不会自动导入不存在的示例插件。

用户数据优先于别名包，别名包优先于插件原名。只改收藏不会覆盖别名包提供的名称。空别名表示回退原名；“恢复别名包 / 原始数据”删除该件服装的用户覆盖。别名包按文件名顺序加载，后面的包覆盖前面的同一件服装。

注册插件时自动创建 `AliasPacks/00_Generated.<插件文件名>.json` 模板，填充全部扫描服装的原名与当前识别部件；已有模板会保留。选择已注册插件可“重新生成别名包模板”，覆盖该生成文件。编辑后使用“重新加载 JSON 与别名包”载入。

`Wardrobe.json` 先写 `.tmp`，写入关闭成功后备份现有文件，最后使用 Windows 原子替换。错误 JSON 不会替换内存中的原数据，也不会被后续保存覆盖；界面会提示错误，可修正文件后“重新加载”。无效别名包独立跳过并显示文件名和错误。丢失模组的元数据与预设保留。

字体默认使用 Windows 微软雅黑；备注加载独立的小字号字体。可配置其他支持中文的字体路径，修改后重启游戏：

```ini
hotkey_enabled=0
toggle_key=122
ui_scale=1.5
cursor_sensitivity=1.0
font_path=C:/Windows/Fonts/msyh.ttc
font_size=20
small_font_size=16
```

## 安全模式与异常退出恢复

安全模式暂停 SkyWardrobe 的全部外观应用、实时预览、自动换装、多层刷新以及实际装备穿脱/清理；衣柜、预设和服装组仍可编辑保存。它是独立于存档的全局状态，读档或重新加载 JSON 不会解除。

手动进入方式：

- 在 `Data/SKSE/Plugins/SkyWardrobe/` 下创建普通文件，忽略最后一个扩展名后，文件名包含 `SAFEMODE` 即可，不区分大小写。例如 `SAFEMODE`、`enableSafeMode.txt`、`开启SAFEMODE.flag`。仅扫描该目录，不递归、不将目录当触发文件。
- 在 `Data/SKSE/Plugins/SkyWardrobe.ini` 设置 `safe_mode=1`。
- 在 WA 面板的“界面设置”中点击“进入安全模式”。

“界面设置”中的“异常退出后自动进入安全模式”复选框可切换自动保护，默认开启，写入 INI 的 `safe_mode_on_unclean_exit`，下次启动时生效。关闭后，文件、INI 和按钮手动入口仍可使用；切换不会解除当前安全模式。正常模式的主面板顶部不显示安全模式按钮，只有处于安全模式时显示恢复提示与退出按钮。

默认 `safe_mode_on_unclean_exit=1`。插件加载时先检查上一会话的 `SkyWardrobe/Session.running`，再同步写入本次运行标记；正常退出时通过 Windows `ExitProcess` 挂接及 CRT 退出回调，结合引擎 `quitGame` 状态清除标记。残留标记表示上次未正常退出，可能是 CTD、强制结束或断电，并不证明崩溃来自服装。设置 `safe_mode_on_unclean_exit=0` 可关闭自动进入，手动入口仍可用。退出挂接失败会写日志，可能保守地在下次启动进入安全模式。

修复问题服装后，点击“退出安全模式并恢复换装”：先等待修复数据完成保存，删除该目录中全部匹配的触发文件，重新检查是否仍有文件可见，然后恢复换装。保存、删除或运行标记写入失败均保留安全模式并显示错误。MO2 多层同名文件若在删除后重新出现，也会阻止退出。INI 不被自动改写，保留 `safe_mode=1` 会在下次启动再次进入。

恢复时使旧请求和自动搭配快照失效，保留轮换进度，按修复后的当前数据重新计算。运行中进入无法撤回已经提交给 SOS/引擎的调用。此模式拦截 WA 发起的操作；SOS 自己从存档恢复的问题外观，以及原版已穿戴装备在读档时崩溃，不在该拦截范围内。

## 构建与验证

保留此目录已有的 CommonLibSSE-NG、vcpkg、CLion CMake 与 Visual Studio 2022 工具链。若从空目录准备，CommonLibSSE-NG `ng` 分支放入 `extern/CommonLibSSE-NG`，vcpkg 放入 `extern/vcpkg`；第三方依赖由现有 manifest 管理。nlohmann/json 3.12.0 的官方单头文件与 MIT 许可证随源码保存。

按项目要求，在提权 PowerShell 中从项目根目录运行：

```powershell
.\scripts\Build-Debug.ps1 -Fresh
.\scripts\Build-Debug.ps1
.\scripts\Build-Debug.ps1 -Language en
```

默认编译中文。沿用编译期开关 `CAF_UI_LANGUAGE` / `CAF_UI_ZH_CN`，以保持既有 i18n 构建入口兼容。构建目标及 DLL 已改为 **SkyWardrobe**，输出：

```text
build/vs2022/Data/SKSE/Plugins/Debug/SkyWardrobe.dll
```

`vs2022` 预设启用 AUTO_DEPLOY，构建副作用目录已改为 `mods/SkyWardrobe/SKSE/Plugins`。不进行部署检查或 SHA-256 验证。此前项目残留的动画实现与测试不属于本插件构建目标。

数据模型与文件保存测试随同 Debug 构建，可独立执行：

```powershell
.\build\vs2022\Debug\SkyWardrobeModelTests.exe
```
